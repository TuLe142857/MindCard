# Rule 02: API & Data Fetching

## 1. Centralized Axios Instance (`apiClient`)
All HTTP requests must go through a single, configured Axios instance.
- **Location:** Typically `src/shared/api/apiClient.ts`.
- **Interceptors:**
  - **Request:** Automatically attach the Access Token (from Redux or http‑only cookie handling) to the `Authorization: Bearer` header.
  - **Response (Auto‑Refresh & Request Queueing):** Catch `401 Unauthorized` errors.
    - **Request Queueing Rule:** If multiple API calls fail with 401 simultaneously, DO NOT send multiple refresh token requests.
    - Set a flag `isRefreshing = true`.
    - Push all subsequent 401 requests into a `queue`.
    - Once the refresh API call succeeds, update the stored tokens, execute all callbacks in the `queue` to seamlessly retry the original requests, and set `isRefreshing = false`.
    - If the refresh fails, clear the queue and dispatch a logout action.

## 2. STRICT RULE: No Direct API Calls in Components
UI Components (both `pages/` and `components/`) must **NEVER** import or use `axios` or `apiClient` directly.

**❌ BAD:**
```tsx
// Inside a component, don't do this
const fetchDocs = async () => {
  const res = await apiClient.get('/api/documents');
  setDocs(res.data);
};
```

## 3. React Query & Custom Hooks
All data fetching and mutations must be managed by React Query (@tanstack/react-query) and wrapped inside custom hooks. These hooks should be located in the `features/{feature‑name}/hooks/` directory.

- **GET Requests:** Use `useQuery`.
- **POST/PUT/DELETE Requests:** Use `useMutation`.

**✅ GOOD:**
```typescript
// features/documents/api/documentsApi.ts
export const fetchDocuments = async (): Promise<Document[]> => {
  const response = await apiClient.get('/api/documents');
  return response.data;
};

// features/documents/hooks/useDocuments.ts
export const useDocuments = () => {
  return useQuery({
    queryKey: ['documents'],
    queryFn: fetchDocuments,
  });
};

// features/documents/components/DocumentList.tsx
const DocumentList = () => {
  const { data: documents, isLoading } = useDocuments(); // Only use the hook in UI
  // render...
};
```

## 4. Pagination Hook (Default UI with Next / Prev Buttons)
When creating a custom API hook for paginated endpoints, default to an implementation designed for a Next/Prev button UI. (The developer will explicitly state in the prompt if an infinite scroll UI is needed). The hook's parameters should include `page`, `limit`, and any other API-specific inputs.

## 5. Agent Context: Backend API Reference
When generating API calls or TypeScript interfaces:
- **ALWAYS** refer to [API_DESC.md](../../../backend/docs/API_DESC.md) (for the high‑level API overview).
- **ALWAYS** check [openapi.json](../../../backend/docs/openapi.json) (generated by SpringDoc) to ensure absolute accuracy of endpoint paths, HTTP methods, request payloads, and response schemas.
- **DO NOT** guess or hallucinate backend fields; map them exactly as defined in the spec.
